# 量潮客户支持档案

客户支持领域的开发档案——客户支持过程中沉淀的资产库，qtcloud-support 检索应答与蒸馏写回的单一事实源。

## 组织方式

**按业务线分目录，一个解决方案一个文档**（对齐 journal 的业务线分组惯例）：

```
data/profile/
├── README.md            # 本索引
└── qtclass/             # 实训基地解决方案（课堂+招聘+众包一体）
    ├── README.md        # 业务线索引
    └── {solution}.md    # 一条解决方案一个文档
```

- 目录 = 业务线（qtclass、qtdata、qtcloud……），随支持对象扩展；其他业务线有条目时再建目录
- 文档名 = 解决方案的英文短横线命名（如 `voucher-usage.md`）
- 新解决方案先入业务线目录，登记进该目录的 README 索引

## 条目格式

```markdown
# {问题一句话}

## 适用场景        # 什么样的情况命中这条
## 解答            # 步骤或答案本体
## 升级判据        # 什么情况AI答不了，要转人工
## 来源与复用      # 指回journal案例 + 命中记录
```

## 与其他层的关系

| 层 | 装什么 | 形态 |
|---|---|---|
| `data/journal/` | 原始案例流（谁、何时、问什么、怎么答） | 时序，一天一文件 |
| `data/profile/`（本库） | 蒸馏出的解决方案条目 | 主题，持续修订 |
| `data/archive/` | 失效/被替代的条目冷存 | 迁移不删除 |

- journal 案例的「沉淀」字段是条目的种子；条目「来源与复用」记复用——复用率由此可数
- 客户是谁的事实档案归 quanttide-customer 域，本库只放支持知识，不写客户事实
